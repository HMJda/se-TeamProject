# 🏪 편의점 통합 운영 프로그램

[cite_start]동의대학교 소프트웨어공학 5조 팀 프로젝트입니다[cite: 2, 6].

## 1. 프로젝트 개요
[cite_start]기존 편의점 시스템은 결제 및 재고관리를 담당하는 포스기와 발주를 진행하는 웹사이트가 분리되어 있어 업무 처리에 불편함이 존재합니다[cite: 13, 43]. [cite_start]이를 해결하고자 판매, 발주, 재고 관리, 반품, 실적 조회 등의 기능을 하나의 Windows 데스크톱 프로그램으로 통합하여 개발했습니다[cite: 14, 25, 44].

* [cite_start]**개발 기간:** 2024. 03. 22 ~ 2024. 06. 07 [cite: 16]
* [cite_start]**개발 방법론:** 원형 모델 (Prototyping Model) [cite: 26, 72]

## 2. 사용 기술 (Tech Stack)
* [cite_start]**Language:** C# [cite: 24, 25]
* [cite_start]**Database:** Oracle [cite: 24, 30]
* [cite_start]**IDE & Tool:** Visual Studio [cite: 24, 72]
* [cite_start]**OS:** Windows 10 [cite: 24, 30]

## 3. 주요 기능 (Key Features)

### 🛒 판매 및 결제 관리
* [cite_start]바코드(제품번호) 입력을 통한 상품 판매 등록 및 취소 기능[cite: 419, 421].
* [cite_start]총 결제 금액 산출 및 Oracle DB 연동을 통한 영수증 테이블 데이터 저장[cite: 1010, 1036].

### 📦 발주 및 재고 관리
* [cite_start]즉석조리, 과자류, 음료 등 카테고리별 검색 및 제품명/바코드 검색을 통한 발주 시스템[cite: 224, 237].
* [cite_start]발주된 데이터를 기반으로 실제 매장 재고 테이블에 정보를 등록하고 연동하는 기능[cite: 237, 239].
* [cite_start]편의점 내 전체 재고 현황 조회 및 검색 기능[cite: 241, 243].

### 📊 실적 및 이익률 조회
* [cite_start]달력(DateTimePicker)을 활용한 영업일자별 당일 판매 실적 조회[cite: 339, 450].
* [cite_start]일별, 월별, 대분류(카테고리)별 판매 실적 분석 및 화면 출력[cite: 339, 469].
* [cite_start]제품의 원가 및 판매가를 계산하여 전년도/올해 월별 이익률을 조회하는 기능[cite: 305, 311].

### 🔄 반품 및 환불 처리
* [cite_start]영수증 번호 및 날짜 검색을 통해 기존 판매 내역을 조회하고 환불을 등록하는 기능[cite: 327, 329].
* [cite_start]환불 처리 시 재고 테이블에 상품 개수를 롤백(추가)하는 기능[cite: 329, 601].

## 4. 데이터베이스 아키텍처 (Database Architecture)
[cite_start]Oracle DB를 활용하여 총 8개의 주요 테이블로 구성되었습니다 [cite: 30, 926-929].
* [cite_start]**회원 (User):** 관리자 및 직원 계정 정보 관리[cite: 88, 926].
* [cite_start]**제품 (Product) & 카테고리 (Category):** 회사에서 공급하는 전체 상품의 기준 정보[cite: 88, 927].
* [cite_start]**재고 (Inventory):** 편의점 내 실제 보유 중인 상품의 수량 및 정보[cite: 86, 929].
* [cite_start]**영수증 (Receipt) & 영수증상세:** 판매 완료된 거래 내역 및 결제 금액 저장[cite: 88, 929].
* [cite_start]**발주 (Order) & 반품 (Return):** 제품 입고 및 반품 처리 내역 기록[cite: 86, 929].

* [cite_start]**단위 테스트 (Whitebox Testing):** 발주 등록 시나리오에서 분기 커버리지(Branch Coverage) 테스트를 수행했습니다[cite: 1149, 1151].
* [cite_start]**예외 처리:** 체크박스 선택 누락, 발주 인덱스 오류, 발주량이 재고량을 초과하는 상황 등의 예외를 식별하고, 알맞은 경고창 메시지 출력 및 디버깅을 완료하여 시스템의 안정성을 확보했습니다[cite: 1151, 1154].
